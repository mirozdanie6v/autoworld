# AUTO MIR — соответствие бизнес-обещаниям канала

Источник канона: закреплённое описание бизнес-модели AUTO MIR, переданное владельцем проекта 25.09.2026.

## Порядок работ

### Этап 1 — два сценария покупки
Статус: **завершён**.

- Клиент выбирает один из двух сценариев: **Аукцион США** или **Авто в Грузии**.
- Корея и Европа исключаются из нового клиентского пути.
- Клиентский каталог показывает только автомобили сценариев США/Грузия.
- Карточка автомобиля явно показывает сценарий.
- Аукционные дата/завершение применяются только к автомобилям из США.
- Для автомобиля в Грузии аукционный этап не показывается.
- Расчёт различает структуру США и Грузии; для Грузии аукционный сбор принудительно равен 0.
- Старые записи с другими origin не удаляются: менеджер может видеть и редактировать их как архивные данные.

### Этап 2 — четыре этапа оплаты
Статус: **завершён**.

Для сценария **Аукцион США** действует фиксированный график:
1. Аукционный аванс — 25–30% от согласованной итоговой стоимости, до торгов.
2. Автомобиль + аукционные сборы — после победы.
3. Логистика и легализация — за несколько дней до прибытия в порт назначения.
4. Таможенные платежи ФТС — за 1–2 дня до пересечения границы РФ.

Правила реализации:
- заказ по США нельзя создать, если аванс меньше 25% или больше 30%;
- сумма четырёх этапов всегда равна согласованной стоимости заказа;
- каждый платёж привязан к конкретному этапу;
- следующий этап оплаты недоступен, пока предыдущий не закрыт;
- по каждому этапу показываются сумма, срок, оплачено, остаток и статус;
- клиент, менеджер и директор видят один и тот же график;
- старые платежи мигрируются по этапам без изменения общей оплаченной суммы;
- если для старого заказа точный первоначальный аванс неизвестен, план помечается как требующий сверки;
- для сценария **Авто в Грузии** четыре аукционных этапа не навязываются: сохраняется согласованный индивидуальный график, пока бизнес не зафиксирует отдельный канон оплаты.

### Этап 3 — досье проверки автомобиля
Статус: **завершён**.

Для сценария **Аукцион США** к расчёту привязано досье конкретного лота:
- LOT / номер лота;
- VIN;
- год и пробег;
- повреждения / состояние;
- фото автомобиля до покупки;
- ссылка на отчёт проверки и/или краткая история автомобиля;
- дата проверки;
- итог: «Одобрен к покупке», «Требует дополнительной проверки» или «Не рекомендован».

Правила реализации:
- расчёт можно подготовить и отправить до завершения проверки;
- перевести расчёт в статус **«Согласован»** для США нельзя без полного досье;
- согласование доступно только при итоговой отметке **«Одобрен к покупке»**;
- фото проверки загружаются в Object Storage и привязаны к досье;
- клиент видит досье в своей заявке до выкупа;
- менеджер видит досье в расчёте, директор — через зафиксированные данные сделки;
- после согласования расчёта досье блокируется от изменения;
- LOT и VIN из проверенного досье автоматически переносятся в создаваемый заказ.

### Этап 4 — очистка клиентского канона
Статус: **завершён**.

- В клиентском интерфейсе разрешены только два сценария: **Аукцион США** и **Авто в Грузии**.
- Новые лиды менеджера и новые автомобили каталога также создаются только в одном из этих двух сценариев.
- Публикация автомобиля с архивным/неопределённым origin блокируется.
- Старые значения origin не удаляются: в существующих внутренних карточках они доступны только как архивные значения и не выводятся клиенту.
- Корея и Европа отсутствуют в новом клиентском пути.
- Ограничения по маркам **не вводились**, поскольку точный утверждённый список брендов не предоставлен.
- «Кавказус», «Глобал авто импорт», доля рынка и формулировки про запрет отдельных производителей **не публикуются** без отдельно подтверждённых формулировок/источников.
- Эти ограничения закреплены smoke-тестами, чтобы неподтверждённые обещания не вернулись при следующих изменениях.

## Принцип внедрения

Каждый этап — отдельный атомарный набор изменений с тестами и возможностью отдельного отката. Следующий этап не должен ломать уже работающие каталог, CRM, логистику и роли.
